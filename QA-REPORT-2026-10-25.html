The recurring failure mode found is output that renders clean and plausible while being wrong — input conventions, helper text and range branches, not the arithmetic.

Proposed fix order

  1. Pick the two that could change a drug dose or a device decision: PD catheter cm-as-inches lock volume; dialyzability wrong flags (isoniazid, metformin-CRRT, methotrexate, ertapenem, sulbactam).
  2. Pick the ones that teach the operator wrong: recirculation "50 mL/hr" method text; CRRT circuit "214 → 2:14" helper promise.
  3. Pick the fail-flippers: PD Kt/V D/P ceiling; recirculation impossibility guard; citrate 200 mL/h current-rate check.
  4. Batch the shared robustness work once (input bounds, NaN guard, clear-on-edit, dead analytics removal, dead CSS, citation fixes) — one pattern, eight apps.

Findings by app

Findings ranked moderate → minor. Each includes the coded line and a concrete input → wrong-output scenario.

1 moderatePD catheter fill/lock volume pd-catheter-calculator.html

  • ✓0.0548 mL/cm constant is real (BC Renal, from Mujais/Crabtree) — reproduces their published lumen table: 42 cm → 2.30, 47 cm → 2.58, 62 cm → 3.40
  • ✓inch→cm conversion internally consistent; arithmetic and rounding clean; no div-by-zero/NaN path
MODERATE

91/92/175/184-185 cm-as-inches input trap — ×2.54 over-estimation of the lock volume

The published procedure multiplies catheter length in cm by 0.0548. This app takes inches and multiplies by 2.54 internally. A nurse with a standard 42 cm Tenckhoff types “42” → app outputs 5.84 mL instead of 2.30 mL (+2 mL set → 7.84 vs 4.30). That flows directly into a heparin-lock or alteplase instillation amount — wrong drug volume, looking precise on screen. The “common sizes 12–22” hint matches inches, so nothing in the app warns about the wrong convention.

Fix: switch the input to cm (drop the 2.54), or accept either with the unit spelled out next to the field and a size-range hint that matches.

MINOR

2 moderatesHD recirculation hd-recirculation.html

  • ✓Formula is the standard KDOQI two-needle three-sample equation, %R = (P−A)/(P−V)×100, matching the app's own citation
  • ✓P↔A swap guarded (negative-numerator alert with instructive message); zero/negative denominator guarded; NaN never reaches display; <10 / 10–15 / >15 thresholds internally consistent
MODERATE

88, 142 Method text says “50 mL/hr” — the published slow-flow technique runs at ~50–120 mL/min

The text also conflates the stop-pump method with a clamp-until-alarm variant and omits the equilibration wait. At 50 mL/hr the pump alarms immediately; an under-equilibrated arterial draw reads falsely high → recirculation inflates → a healthy access gets referred for an unnecessary workup. Fix is text-only, but it teaches the procedure.

MODERATE

180-194 No impossibility ceiling — the A↔V swap renders “800.0% Significant”

P=60, A=20, V=55 (samples swapped) passes both existing guards and displays 800%. Negatives pass too (no min="0"). Physiologically this method tops out well under ~80%; anything above is a sampler-order or lab error and should trigger a “recheck the samples” message.

MINOR

184-191 status classes are assigned but don't exist in the stylesheet — every result renders in the same static green; severity color never happens · 165 typing “0” (a real-world typo) gives the confusing “fill in all fields” · Schneditz 1992 citation supports the formula without its own caveat (that paper explains why this method overestimates access recirculation) · Salimi 2008 volume/PMID unverified before reuse as a footnote

MODERATE

MODERATE

Cross-app patterns

  • •Three apps POST analytics to a dead endpoint (countapi.xyz shut down years ago) — harmless, removes with one line each
  • •No numeric input is bounded anywhere — negatives, zero and absurd magnitudes all render; the fix pattern (bounds + NaN guard + “clear outputs on edit”) is one shared snippet
  • •Citation drift is cosmetic but real: “KDOQI 2025” is 2015 thresholds; KDIGO/KDOQI footer on the dialyzability table is decorative; one reference's volume/PMID unverified
  • •Clean-on-submit is inconsistent: some apps clear stale outputs on any input change, others keep the previous result until re-submit — an interrupted user can read a consistent-looking stale result in at least 4 apps

Method & sources

Eight apps reviewed in full via four parallel reviewers; every boundary/branch claim re-executed in isolated JavaScript, not just read. Clinical values verified against: FDA labels (LEVAQUIN, CUBICIN, Invanz/ertapenem), EXTRIP (metformin, lithium), BC Renal PD procedures (0.0548 mL/cm, transfer-set volumes, alteplase instillation), published Watson/TBW equation tables, KDOQI HD 2015 + PD adequacy targets, and the KDOQI two-needle recirculation method. Policy IX-11 citrate table values are local-protocol transcription — verified for direction/structure, not against the policy document itself. The fix plan above changes labels, text, flags and validation only — every verified formula stays exactly as is.
